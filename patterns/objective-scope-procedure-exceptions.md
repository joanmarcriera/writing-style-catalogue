# Objective / Scope / Procedure / Exceptions

Use this pattern when a document needs to tell people exactly how to perform or govern a repeatable activity.

## Structure

```text
Objective: [What this procedure is intended to achieve]
Scope: [Who, systems, cases, and boundaries covered]
Procedure: [Numbered steps with owners, inputs, outputs, and checks]
Exceptions: [When the procedure does not apply and who can approve deviation]
```

## Good for

- SOPs
- Runbooks
- Access request procedures
- Policy implementation guides
- Finance or tax process notes

## Prompt line

```text
Structure the output as Objective / Scope / Procedure / Exceptions. Make every procedure step an action and define who can approve exceptions.
```

## Quality check

- Scope has clear boundaries.
- Steps are sequential and testable.
- Exceptions are controlled, not open-ended.
- The procedure includes records or evidence to retain.
