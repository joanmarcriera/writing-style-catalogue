# Checklist: Technical Document Review

Before publishing technical documentation.

## Content Accuracy

- [ ] All technical information is correct and current
- [ ] Code examples are tested and working
- [ ] Commands and APIs match actual system
- [ ] Version information is specified
- [ ] Known limitations are documented
- [ ] Troubleshooting covers real issues

## Usability

- [ ] Overview explains what document covers
- [ ] Prerequisites are explicit
- [ ] Step-by-step instructions are clear
- [ ] Examples show realistic use cases
- [ ] Diagrams or visuals aid understanding
- [ ] References or links are current

## Completeness

- [ ] All required topics are covered
- [ ] No gaps in information
- [ ] Troubleshooting section covers common issues
- [ ] Clear next steps or further reading
- [ ] Glossary for technical terms
- [ ] Contact info for questions

## Clarity

- [ ] No unexplained jargon
- [ ] Assumptions about audience knowledge stated
- [ ] Technical precision without being obscure
- [ ] Consistent terminology throughout
- [ ] Easy to scan (headings, lists, tables)

## Maintenance

- [ ] Date of last update visible
- [ ] Owner/maintainer identified
- [ ] Plan for keeping current documented

---

Technical accuracy is non-negotiable.
